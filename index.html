EasyXport guide

EasyXport runs inside Jira Cloud on Atlassian Forge. A Jira administrator installs the app. Each user can export only the issues they can already view in Jira.

Export one issue

  1. Open a Jira issue you can view.
  2. Open the EasyXport issue panel.
  3. Choose a template and a file type.
  4. Start the export and save the file when it is ready.

Export a JQL search

  1. Open EasyXport from Jira’s Apps menu.
  2. Enter a JQL query, such as project = DEMO ORDER BY updated DESC. Replace DEMO with your project key.
  3. Run the search and review the results.
  4. Choose a template, select PDF, DOCX, XLSX, CSV or JSON, and export.

Bulk exports support up to 5,000 issues. Progress shows while issues load. A large report may take longer to create in your browser.

Save a private template

Choose the fields you want, add a report title and color, and choose whether to include a cover page. Save the template to use it again. Your templates are private to your account.

Prepare scheduled reports

Create a schedule using a JQL query, template and hourly, daily or weekly interval. Each run saves a selection of up to 1,000 issue keys. Open EasyXport to download the latest report. Downloads fetch current details and check your current Jira access. Reports are not emailed.

What can be included?

Depending on the selected template and your Jira permissions, reports can include fields, descriptions, comments, work logs, subtasks, linked issue summaries and attachment names. Attachment files themselves are not embedded.

Formats

  • PDF: a report to read and share.
  • DOCX: a Word document you can edit.
  • XLSX: an Excel workbook for sorting and analysis.
  • CSV: table data for other tools.
  • JSON: structured issue data.

If an export fails

Check that the JQL query works in Jira and that you can open the requested issues. Try fewer issues or fewer optional fields. Keep the browser tab open until the download is ready. If the problem continues, contact support with the format, approximate issue count and error text. Do not send private issue content or login details.

Current release limits

EasyXport does not include uploaded Word or Excel templates, email delivery, customer-portal exports, scripting or a public export API. The interface and support are in English.

Privacy policy

Updated October 28, 2026

EasyXport is provided by Ben Lam, using the BenDevApps publisher name. Contact: bendevelopingapps@gmail.com.

Jira report processing uses Atlassian Forge. EasyXport does not send Jira report data to our website or an outside report server.

What the app reads

The app reads Jira issues you request, including selected fields, descriptions, comments, work logs, subtasks, linked issue summaries, and attachment names. It uses your Jira permissions.

What the app stores

Forge stores your templates, schedules, creator account ID, and selected issue keys for the latest scheduled report. It does not keep the issue descriptions, comments, or people names in report storage. Templates and schedules are private to their creator. Scheduled reports contain up to 1,000 issue keys. Downloads fetch current issue details using your access.

Atlassian account privacy requests

The app periodically reports stored creator account IDs to Atlassian's privacy API. If Atlassian asks us to erase or refresh a person's stored data, their saved templates, schedules, and report selections are removed. They can create fresh reports if their account remains active.

How we use data

Data is used to make the exports and schedules you request, manage access, and answer support requests. We do not sell Jira or personal data, use it for advertising, or use it to train AI models.

Support

Email support is processed by Gmail. Our public documentation website uses GitHub Pages. Support requests are sent by email; this website has no support form. Information you send is used to answer your request. Do not include passwords, API tokens, or confidential Jira content.

Keeping and deleting data

You can delete your own templates and schedules. Deleting a schedule deletes its saved report data. A new scheduled run replaces the previous report. After uninstalling, any remaining Forge data follows Atlassian's hosted-storage retention policy rather than disappearing instantly. Support messages are kept only as needed for support and normal business records.

Your choices

Security

Updated October 28, 2026

Built on Atlassian Forge

Jira requests, templates, schedules, and scheduled report data are processed inside Atlassian's platform. The app uses Jira read permissions and Forge storage.

No outside report server

PDF, Word, Excel, CSV, and JSON files are built in your browser. EasyXport does not upload these reports to our website.

Your Jira access still applies

Exports use your Jira permissions. Scheduled jobs run on behalf of the user who created them, not an all-access app account. Templates and schedules are private to their creator. When you download a scheduled report, EasyXport checks current access and refreshes the issue details. This prevents old reports from exposing issues you can no longer see.

Data protection

Atlassian isolates Forge storage by app installation. Deleting a schedule also deletes its stored report. The installed EasyXport app does not store Atlassian passwords or API tokens. The developer's deployment credentials are separate from the installed app.

Release checks

We use automated tests, dependency audits, lint checks, and production builds. These checks do not replace a customer's own security review.
